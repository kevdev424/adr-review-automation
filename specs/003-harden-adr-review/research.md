# Phase 0 Research: Harden ADR Review PR Commentary

All Technical Context items were resolved directly from the existing repository (features 001/002 already established the stack); no open unknowns required external research. This document records the key decisions for traceability.

## Decision: Where accepted-baseline eligibility is computed

- **Decision**: Compute "which ADRs count as an accepted conflict baseline" (status is `Accepted`/`Approved` case-insensitive, and `superseded_by` is empty) deterministically in `.specify/scripts/powershell/review-adr.ps1`, not inside the Copilot CLI prompt.
- **Rationale**: This is a mechanical front-matter filter, not a judgment call. Doing it in PowerShell makes it unit-testable via the existing `tests/review-adr-tests.ps1` harness and removes ambiguity/variance that would come from asking an LLM to interpret status values on every run.
- **Alternatives considered**: Ask the Copilot CLI prompt to interpret status fields itself. Rejected because LLM output for the same input could vary run-to-run, and the clarified business rule (Accepted/Approved, excluding superseded) is precise enough to be trivially deterministic.

## Decision: How the "no reasoning" constraint is enforced

- **Decision**: Update the `review-adr` skill (`SKILL.md`) and the local prompt (`review-adr.prompt.md`) to explicitly instruct the model to output only final conclusions about the ADR — no narration of steps taken, no "let me check" style language — and to keep the existing informational/blocking summary structure otherwise unchanged.
- **Rationale**: The review is generated by an LLM (Copilot CLI); the only lever available is the prompt/skill contract itself. There is no separate "reasoning channel" being leaked today — the current prompt simply doesn't forbid narrative language, so tightening the instruction is sufficient and requires no new tooling.
- **Alternatives considered**: Post-process model output to strip narration via regex/heuristics. Rejected as fragile and likely to produce false positives/negatives; a clear prompt contract is more reliable and simpler.

## Decision: How conflicts-first, fixed-heading formatting is enforced

- **Decision**: The skill/prompt contract mandates a literal heading (e.g., `## ⚠️ Conflicts with Accepted ADRs — Do Not Merge`) as the first line of output whenever the model determines an obvious conflict exists against an eligible accepted ADR; the heading is omitted entirely when no conflict is found. The CI workflow's fallback text (used when the Copilot CLI invocation fails) is updated to never claim conflicts were checked or absent.
- **Rationale**: A fixed, literal heading is easy for both human reviewers (skimmable) and for future tooling/tests (grep-able) to detect reliably, directly satisfying the clarified requirement.
- **Alternatives considered**: Free-form prose without a fixed marker. Rejected during clarification because it can't be reliably detected by tests or skimmed as quickly by reviewers.

## Decision: Testing approach

- **Decision**: Extend the existing plain-PowerShell test harness (`tests/review-adr-tests.ps1`) with new fixtures — an active accepted ADR, a superseded accepted ADR, and a proposed ADR that obviously conflicts with the active one — and assert that `review-adr.ps1`'s eligibility computation includes/excludes the right fixtures. LLM-authored final commentary (reasoning-free prose, fixed heading placement) is validated via the same harness by asserting the presence/absence of the fixed heading string and the absence of common narration phrases in any local dry-run fixture output, consistent with the project's existing "no new test framework" convention.
- **Rationale**: Keeps the same testing stack and conventions already used by the repository (feature 002 introduced this harness); avoids introducing Pester or another framework for a small, additive scope.
- **Alternatives considered**: Introduce Pester for richer assertions. Rejected — unnecessary framework churn for a small set of additional assertions that fit the existing harness's style.
